# Independent TKGPU Python binding

The native host ABI is versioned by Kerbot Microsystems, not by Tcl/Tk.
Build and bundle on the host:

```sh
cmake -S TKGPU -B TKGPU/build
cmake --build TKGPU/build --config Release --target tkgpu_host_bundle
```

The bundle contains the native library and a Python package; it does not need
the original _tkinter.pyd/.so. Add the bundle's python directory to the
application-local module path, then instantiate `tkgpu.Host(library)`.
The opt-in `tkgpu.tkinter_adapter.install(library)` must run before any
`import tkinter`. It provides string-result Tkinter API compatibility only.

For the experimental Kerbot source launcher, set
`KERBOT_TKGPU_HOST_BRIDGE=1` and optionally `KERBOT_TKGPU_RUNTIME_DIR` to
the bundle directory. The isolated startup probe must still pass; no original
Tk fallback occurs. The default launcher remains on the previous experimental
compatibility bridge pending regression evidence. Native third-party extensions
requiring a real Tcl_Interp (including some image integrations) cannot use
this opaque host handle; typed results and cross-thread dispatch are also
not yet implemented.

Use separate native builds for Windows x86/x64, Linux and each qualified OS.
Win95/98 requires a proven x86 toolchain, CRT, compatible Python/ctypes
runtime and actual VM tests. macOS native GUI backend remains unimplemented.

ABI 1.1 adds a separate revision check, owner-thread validation in the native host, explicit signed 64-bit integer/finite-double/boolean conversion, and side-effect-free list joining. Python `call_typed(kind, *args)` supports string, integer, double, boolean and list. Default calls preserve strings; this is not full Tkinter wantobjects parity. Existing ABI 1.0 symbols remain available, but the updated Python binding needs revision 1 or higher.

Cross-thread requests: `host.submit_call(*args)` returns a Future and never calls the native API on the producer thread. The owner must run `mainloop()` or explicitly call `drain_calls()`; pending requests are cancelled on close, and the queue is bounded. This is an explicit API, not transparent cross-thread compatibility for all Tkinter methods. Do not wait on a pending Future from its owner thread. Direct calls on a foreign thread are still rejected. Close handles explicitly on their owner thread; abandoned native handles may leak rather than destroying them from a foreign thread.

ABI 1.2 adds `TKGPU_HostCallResult` (one FFI round trip for command plus result) and bounded, exact-size RGBA8 photo read/write. Direct full-image replacement uses a bulk copy rather than pixel conversion. No speedup is claimed until measured. ABI 1.2 retains the previous symbols; its Python package requires revision 2.

Direct Tkinter photo loading now decodes PNG and other Pillow-supported sources using Python and transfers the RGBA bytes through ABI 1.2. The direct Kerbot loader installs an ImageTk.PhotoImage/getimage adapter if Pillow is present. It does not expose a Tcl_Interp address. BitmapImage, arbitrary photo operations and the complete external extension API remain outside this implementation. Run the existing widget benchmark with `--direct --candidate TKGPU/build/tkgpu-host` to compare with stock Tk. It measures command throughput, not presented-frame latency.

The Tkinter adapter now marshals call, command registration/deletion, list/scalar conversion and RGBA transfers from a worker thread to the owner mailbox. Owner mainloop or root.update() must pump the queue. A queued operation times out after five seconds and is cancelled if not yet started; already running operations are not retried. Nested native waits and unsupported extension APIs still require additional qualification.

Host callbacks now register directly in the core command registry, eliminating the intermediate Tcl object allocation for each UTF-8 argument. Active callbacks retain their context until they return, including self-unregister/replacement. Script parser storage starts at eight 4096-byte slots rather than reserving 1024 slots for every evaluation; grows on demand and keeps nested storage separate. This is a reduction in initial reserved capacity, not a measured RSS or speed claim.

ABI 1.3 adds tagged core results for list, llength, integer expr, catch and info exists. The Python Tkinter adapter honors wantobjects for these known types; arbitrary text (including numeric-looking strings) and untagged widget results remain strings. Full Tcl object identity, typed widget results and arbitrary precision object parity remain open. The direct Host.call() retains its string contract; Host.call_tagged() opts into the new result metadata.

### Direct-host qualification

Build `tkgpu_host_qualify` on Windows or on Linux with a working X11 display (e.g. under xvfb). It builds the independent bundle and native ABI test, runs the native and Python checks and the isolated Kerbot GUI probe, and writes `tkgpu-host-qualification.json`. A skipped test, missing display, failed subprocess or missing probe token prevents qualification. This is a source-mode smoke gate only; full Kerbot regression and real benchmark evidence remain separate release gates. The old bridge remains available explicitly while the direct bridge is opt-in.

The host bundle now includes the repository license, host header and development/distribution checklist, with an explicit SHA-256 inventory and no automatic third-party binary copying. Use a fresh output directory if an earlier bundle contains extra files (including Python bytecode). Use Python -B for direct-host test runs. This is not commercial release authorization; see the legal checklist.

The native callback registry now uses an on-demand open-addressed name index for 16 or more commands. It retains full string equality, tombstone/swap-removal correctness and a linear fallback on allocation failure; smaller registries allocate no index. This reduces the expected lookup complexity from O(n) to O(1), not a measured application speedup. Original TKGPU implementation; no external source or new dependency added.

ABI 1.4 adds double and numeric-list result tags and explicit built-in result contracts for selected Canvas, Listbox, Treeview, geometry, image and window queries. Numeric-looking user text and Treeview identifiers are not coerced. Existing ABI symbols remain; the updated binding requires revision 4. This is a partial parity improvement, not an assertion that all widget behavior or typed objects are complete.

Treeview viewport operations see, bbox and identify now perform real row/column traversal with the same row heights, scroll offsets and stretched column widths as painting. Added sibling index/next/prev and item option-list queries. The implementation remains a subset (e.g. arbitrary displaycolumns and all theme elements are not fully supported). No external source code was imported.

Treeview cell get/set and item relocation now operate on stored values and the native tree hierarchy. Cycle-producing moves are rejected. Read-only Treeview queries skip unnecessary native invalidation. These are original project changes and add no external dependency.

ABI 1.4 maintenance: opt-in Text undo/redo delta history, separator/reset/canundo/canredo, undo/autoseparators/maxundo configuration and clean-revision tracking. Native edit operations and keyboard edits use the same journal; no whole-document history copies or allocation when undo is disabled. History is bounded to 16 MiB and 4096 records per document, with oldest groups evicted (an oversized single group can be dropped). Render snapshots intentionally do not copy history. The journal stores only deleted/inserted UTF-8 bytes. Replay inherits the intersection of surrounding tags, matching the reference behavior for isolated and adjacent tags. Disabled recording invalidates history on the next edit, unlike Tk's historical behavior. Automatic grouping joins consecutive operations of the same type even at different positions; explicit separators break the group. Disabled-state replay safely rejects the operation without consuming history. Full Tk edge semantics and <<Modified>> events are not asserted. The revised journal and extracted native document mutation/replay functions passed a standalone C harness under ASan/UBSan (10,000 recorded edits and 8,192 undo/redo replays; UTF-8 validation test double). Full native regression tests still require execution. No external source or public ABI revision changes.
